# План реализации авторизации на фронтенде

## Цели
1. Добавить окно авторизации на фронтенд
2. Реализовать возможность игры гостем (без авторизации)
3. Обновлять рекорды авторизованных пользователей в базе данных

## Архитектура

### Состояние авторизации
- Глобальное состояние для хранения информации о пользователе
- Проверка авторизации при загрузке приложения через API
- Использование httponly cookies для безопасного хранения токенов (уже реализовано на бэкенде)

### Компоненты для создания

#### 1. AuthModal (Модальное окно авторизации)
- Форма входа/регистрации
- Переключение между режимами входа и регистрации
- Обработка ошибок авторизации
- Кнопка "Играть как гость"

#### 2. AuthContext (Контекст авторизации)
- Управление состоянием авторизации
- Методы для входа/выхода/регистрации
- Проверка авторизации при загрузке

#### 3. AuthProvider (Провайдер контекста)
- Обертка для всего приложения
- Инициализация состояния авторизации

#### 4. ProtectedRoute (Защищенные маршруты)
- Компонент для защиты маршрутов (если понадобится)

### API интеграция

#### Расширение client.ts
- Добавить методы для работы с пользователями
- Добавить методы для обновления рекордов
- Обработка ошибок авторизации (особенно 401 для автоматического logout)
- Использование существующего withCredentials: true для работы с cookies

#### Новые API endpoints для использования
- `POST /auth/login` - вход
- `POST /auth/register` - регистрация
- `POST /auth/logout` - выход
- `GET /auth/me` - получение информации о пользователе
- `POST /game_sessions/` - создание игровой сессии (для обновления рекордов)

### Логика игры

#### Для гостей
- Игра без сохранения прогресса в БД
- Локальное хранение лучшего результата в localStorage (только для отображения)
- Отображение уведомления о том, что результат не сохраняется в БД

#### Для авторизованных пользователей
- Автоматическое сохранение результатов в базу данных
- Отображение личного рекорда из базы данных
- Синхронизация с глобальным рейтингом

### UI/UX элементы

#### Главное меню
- Кнопка "Войти" / "Выйти"
- Отображение имени пользователя (если авторизован)
- Кнопка "Играть как гость"

#### Игровой интерфейс
- Индикатор режима игры (гость/авторизованный)
- Отображение личного рекорда
- Уведомления о сохранении результатов

### Состояние приложения

#### Типы данных
```typescript
interface User {
  id: number;
  telegram_id: number;
  username?: string;
  first_name?: string;
  last_name?: string;
  max_score?: number;
  created_at: string;
  updated_at?: string;
}

interface AuthState {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  error: string | null;
  // НЕ хранить токен в состоянии - используется httponly cookies
}
```

### План реализации

#### Этап 1: Базовая структура
1. Создать AuthContext и AuthProvider
2. Добавить базовые типы данных (используя существующие схемы с бэкенда)
3. Расширить API клиент (добавить обработку 401 ошибок)
4. Настроить автоматическую проверку авторизации при загрузке

#### Этап 2: UI компоненты
1. Создать AuthModal компонент
2. Добавить кнопки авторизации в главное меню
3. Создать компонент отображения пользователя

#### Этап 3: Интеграция с игрой
1. Модифицировать Game компонент для работы с авторизацией
2. Добавить логику сохранения рекордов
3. Реализовать отображение рекордов

#### Этап 4: Тестирование и полировка
1. Тестирование всех сценариев
2. Обработка ошибок
3. Улучшение UX

### Безопасность
- Валидация данных на фронтенде
- Обработка ошибок API
