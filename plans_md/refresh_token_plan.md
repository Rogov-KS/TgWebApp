# План добавления Refresh Token в систему аутентификации

## Обзор
Данный план описывает все необходимые изменения для добавления поддержки refresh token в существующую систему аутентификации, которая в настоящее время использует только access token.

---

## 1. Backend изменения

### 1.1. Обновление конфигурации
**Файл: `backend/core/config.py`**
- Добавить `REFRESH_TOKEN_EXPIRE_DAYS: int = 30`
- Добавить `REFRESH_TOKEN_COOKIE_NAME: str = "refresh_token"`

### 1.2. Создание модели RefreshToken
**Файл: `backend/models/refresh_token.py`**
- Создать модель `RefreshToken` с полями:
  - `id` (Integer, primary key)
  - `token` (String, unique, indexed)
  - `user_id` (Integer, ForeignKey к users.id)
  - `expires_at` (DateTime)
  - `is_revoked` (Boolean, default=False)
  - `created_at` (DateTime, server_default=func.now())

### 1.3. Обновление модели User
**Файл: `backend/models/user.py`**
- Добавить связь `refresh_tokens: Mapped[list["RefreshToken"]]`
- Добавить relationship с back_populates

### 1.4. Создание DAO для RefreshToken
**Файл: `backend/dao/refresh_token.py`**
- Создать `RefreshTokenDAO` с методами:
  - `create()`
  - `get_one_or_none()`
  - `get_many()`
  - `update()`
  - `delete()`
  - `count()`

### 1.5. Расширение утилит аутентификации
**Файл: `backend/utils/auth.py`**
- Добавить `create_refresh_token(user_id: int) -> str`
- Добавить `verify_refresh_token(token: str) -> User | None`
- Добавить `revoke_refresh_token(token: str) -> None`
- Добавить `revoke_user_refresh_tokens(user_id: int) -> None`

### 1.6. Обновление API эндпоинтов
**Файл: `backend/api/endpoints/auth.py`**

#### Обновить эндпоинт `/login`:
- Добавить создание refresh token
- Добавить установку refresh token в httpOnly cookie
- Обновить возвращаемые данные (добавить refresh_token)

#### Добавить новый эндпоинт `/refresh`:
- Принимать refresh token
- Валидировать refresh token
- Создавать новый access token
- Возвращать новый access token

#### Обновить эндпоинт `/logout`:
- Добавить отзыв всех refresh токенов пользователя
- Добавить удаление refresh token cookie

### 1.7. Создание миграции базы данных
**Файл: `backend/alembic/versions/xxx_add_refresh_tokens.py`**
- Создать таблицу `refresh_tokens`
- Добавить индексы для производительности
- Добавить внешний ключ к таблице `users`

## 6. Преимущества реализации

### Безопасность:
- Refresh токены хранятся в httpOnly cookies
- Возможность отзыва всех токенов при выходе
- Разные сроки жизни для access и refresh токенов

### Пользовательский опыт:
- Прозрачное обновление токенов
- Автоматическое восстановление сессии
- Отсутствие необходимости повторного входа

### Мониторинг:
- Отслеживание активных сессий
- Возможность принудительного завершения сессий
- Статистика использования токенов
